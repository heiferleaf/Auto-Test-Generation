## 0 核心范式

可视化蒙版是 **CFG 步骤工作台 + 靶机内真实操作捕获层**，不是独立脚本播放器，也不是在网页截图上模拟点靶机。

两条面必须分开：

| 面 | 用户能做什么 | 用户不能做什么 |
|---|---|---|
| **工作台**（本地网页） | 看连接/录制/运行状态；看/编 CFG；插入等待与断言；组织组；运行全部 | **不能**在网页里点出靶机里的真实交互 |
| **靶机**（真实软件） | 开始录制后在软件里点击/输入；点选录制时在软件里点目标元素 | 不能用工作台点击代替这些操作 |

核心链路：

```text
连接靶机
  → 开始录制
  → 用户在靶机内真实操作（点击/输入/选择/提交）
  → 交互实时生成 Step，CFG 实时增长
  → 停止录制
  → 查看 / 编辑 / 删除 / 补充等待与断言
  → 框选或选组，组织为 Sequence / Selection / Loop
  → 运行全部
  → 执行中 CFG 高亮当前步；失败立即暂停并定位
```

**步骤正确性**：按步骤执行，就是用户想在软件里执行的内容。录制必须能完整定位多层 DOM，输入必须坍缩成一次填充。插入的等待/断言必须能设时间和目标。

**编排正确性**：一步默认就是一个组；多选可打包、命名、拆包；选中组可设为选择组或循环组。CFG 以**图形化控制流图**呈现这些结构——顺序串成链、选择分两枝、循环画回环，步骤多时仍可读（折叠/缩放平移）。边只连同一层，像 `{}`。

**交互友好性**：拖拽调序；左键按住框选后弹出「分支组 / 循环组」；等待元素、断言、创建分支组的条件，都要能进入「嵌入式点选录制」，让用户在真实软件里点元素。

## 1 功能边界

| 模块 | 包含 | 不包含（本期） |
|---|---|---|
| 连接 | 自动连默认可配置端口；失败提示重连；未连禁用录制/运行 | 不在网页里模拟靶机点击 |
| 录制 | 开始/停止；靶机内 click/input/change/submit 实时成步 | 不提供手动添加 click/fill/select/submit |
| 点选录制 | 等待元素、断言、选择组条件：进入点选态后在靶机点元素 | 不在截图流上点选冒充靶机点选 |
| 插入 | wait（时长）、waitUntil（元素+超时）、assert（元素或文本） | 不插入 snapshot/note/callScript/setVar |
| 组 | 默认一步一组；打包/命名/拆包；设为顺序/选择/循环 | 不自动依赖检测、不级联删除 |
| 展示 | **CFG 图形化控制流图**统一展示控制流与步骤；步骤多时可折叠/缩放平移 | 不把线性列表当主视图；不挂 Git 版本面板；**不提供 minimap 缩略图** |
| 运行 | 运行全部；失败立即暂停+标红+截图定位 | 不提供「从此处运行」（前置依赖会把语义弄乱）；不静默跳过失败步 |
| 版本 | — | **Git 式 commit/branch/switch/cherry-pick 不进入本期 UI** |

## 2 元素、功能与交互逻辑

### 2.0 工作台布局（信息架构）

本期工作台仍是本地网页（浏览器跑不了 Playwright，真机必须走 Node 桥）。产品名 **测试步骤中台**。靶机内常驻叠加条/浮动钮作为增强项，见 §5 决策 D1。

```text
┌──────────────────────────────────────────────┐
│ 顶部条（加高）：测试步骤中台（更大标题）· 已连接 / 灯 │
│ 开始/停止录制 · 插入步骤 · 运行全部 · 导入/导出/清空 │
├──────────────────────────────────────────────┤
│ 步骤流图（可主可次）        │  预览舞台（可主可次）   │
│ 拖拽调序 · 框选打包         │  每步截图，整张可见     │
│ 详情停在流图栏内叠加        │  不盖预览、无锁台横幅   │
└──────────────────────────────────────────────┘
```
详情停在步骤流图栏内（节点旁叠加），不占常驻右栏，也不盖预览。壳根 `data-layout=flow|shot` 按场景切主栏：

- **录制中**：左侧 CFG 始终主栏。
- **已停止、闲置 / 悬停**：右侧截图主栏。悬停一步超过约 400ms 切该步截图，鼠标离开不撤回。
- **已停止、点一步或框选**：左侧 CFG 主栏；选区边缘出浮动钮（原子：编辑/分支/循环；框选：打包/分支/循环；已打包组：编辑/分支/循环/拆包）。点空白回到截图主栏，保留最后点中步的高亮。
- **运行全部**：CFG 平滑平移/缩放，让当前步停在画布中心（约 260ms），不要跳切。

面板（CFG 壳、预览框、顶栏）用毛玻璃（`backdrop-filter: blur` + 半透明），与窗口边缘留出边距，不要贴齐。**壳根外沿 padding/gap 不随选中、详情开关、`data-layout=flow|shot` 变化**——闲置截图主栏和点选流图主栏底缝一样宽；动作条已进顶栏，双栏主区下面仍靠壳根 `padding-bottom` 留缝，禁止贴死窗口底。`html` / `body` / `#app` 锁死视口（`100vh`/`100dvh`、`overflow:hidden`），禁止整页滚动条；CFG 只在栏内平移。雾块/流体跟指针，只在页面壳（玻璃卡片后面）；**步骤流图画布**用约 20px 间距的低透明点阵铺满整个绘制面/平移世界（不要只盖住树那一小块，也不要铺到顶栏）。右侧预览不是纯黑底。
断言表单顺序：类型 → 点选（若该类型需要）→ 期望值（若需要）→ 最长等待 → 确定。详情右上角扇形 **X** 关闭（不保存）；**不要取消钮**。确定与删除同一行等宽（确定主按钮、删除次要），不要确定缩成左对齐小条、删除独占一整行。`textContains` 有 locator 时只搜该节点文本。拆包只在组的浮动钮上，不进详情。提示文案：`拖拽调序 · 框选打包 · 单选编辑`。

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| 顶部条 | 显示连接/录制/运行 + 主操作 | 第一行可见：**测试步骤中台**（更大标题，约 22px；点阵字标约 36px 高，指针靠近时点散开；`prefers-reduced-motion` / jsdom 停动画）+ **已连接 / 未连接**。第二行：开始录制、插入步骤、运行全部、导入、导出、清空（`[data-action]` 名不变）。靶机窗口完整 `document.title`（如 `1.txt - cursor - Visual Studio Code`）只放在「已连接」的 `title` tooltip。网页标签 `<title>` / `document.title` 固定为「测试步骤中台」。已暂停 / ● 录制中仍用指示灯 |
| 目标下拉 | 切主窗口/WebView | `listTargets().length <= 1` 时隐藏。多个目标时显示，标签「当前窗口」（Electron webview 需要） |
| 录制钮 | 开始/停止录制 | 未连接时禁用。点开始后**必须**到靶机里操作，工作台截图上的点击不产生步骤。录制中 `data-layout=flow` |
| 运行全部 | 从头执行 | 未连接时禁用。失败立即暂停，见 §2.8 |
| 导入 | 用户选本地 JSON 载入当前会话 | **保留**。与对话打开并存，不是唯一入口 |
| 对话打开（MCP） | Agent 生成后把同一份 JSON 推进当前工作台 | 内核 `loadScript`；第一期 MCP Tool 名 **`script.open`**。不替代导入按钮。封装 MCP 时一行调用桥 `loadScript` |
| 插入步骤 | 只增控制类步 | 菜单仅：等待时间 / 等待条件 / 断言。循环与分支走组操作，见 §2.4、§2.5 |
| 步骤流图 | 统一展示全部步骤与控制流（图形化） | 主/次按 `data-layout` 切换。节点不贴齐画布左上角（树有 padding，内容小时水平居中）。点击节点→选中+该步截图（查看，不自动打开详情）。`data-layout=shot` 时点**单步**也在该步包围盒右侧弹出打包簇（顺序/分支/循环），与框选同一套位置算法。点「编辑」或插入步骤→锚在节点旁的紧凑详情。拖拽改顺序。框选打包。组可折叠、画布可缩放平移。**不要 minimap**。流图栏/树 **不要**原生 overflow 滚动条（`overflow:hidden` + 滚轮/拖拽平移）；工作台本身也不要整页滚动条。点阵只在步骤流图画布内（约 20px、低透明、铺满 pan 世界，可有轻微指针斥力），**不要铺到顶栏**；页面壳才是跟指针的雾块。if 每一列只标一次 True/False，枝内 sequence 包装不要再印分支词。出现/消失约 180ms opacity/transform |
| 详情 | 编辑选中步/组 | 锚在**选中节点旁**的紧凑叠加层，不盖住该步节点、不盖预览、不吃掉半幅流图、不在 CFG 栏中缝拉出原生滚动条。弹层内部 `[data-inspector-scroll]` `overflow:auto`，`max-height` 跟视口走，长表单在弹层里滚。入口只在步骤条/打包簇/详情本身，预览栏没有「编辑」。组节点隐藏点选「尚未选取」。右上角扇形 **X**（`[data-inspector-close]`）关闭且不保存；**确定**=保存、**删除**=删除，同一行等宽（确定主按钮、删除次要），不要确定缩成左对齐小条、删除独占一整行；**不要取消钮**。Esc、点舞台或 CFG 空白关闭。保存后详情仍在并给出 `[data-save-notice]` / 按钮「已保存」。**不要**在详情里再放「设为选择组/设为循环组」。双栏主次切换过渡 `grid-template-columns` |
| 截图台 | 每步一张靶机截图 + 高亮 | 不是实时渲染软件画面。预览整张可见，**不要**锁台横幅/遮罩。「预览不可操作靶机」只写在 MCP Skill，不写进舞台 |

### 2.1 连接

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| 连接指示 | 显示是否连上靶机 | 启动后自动连默认可配置调试端口（默认 9222，须能被环境变量/`?cdp=` 覆盖，禁止写死到唯一路径且不可改） |
| 失败态 | 提示并允许重连 | 未连接 → 提示失败原因 + 重连入口；开始录制与运行全部不可用 |
| 目标选择 | 切主窗口/WebView | `listTargets().length <= 1` 时隐藏。多个目标时显示并标「当前窗口」。选择器不能写死应用名 |

### 2.2 录制：用户操作步的唯一入口

用户操作类步骤（点击 / 填充 / 选择 / 提交）**只能**由「开始录制」在靶机里捕获，工作台不提供手动添加。

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| 开始录制 | 注入监听 | 向当前及后续出现的 target 注入 click/input/change/submit；顶部进入 ● 录制中 |
| 实时生成 | 边操作边出步 | 每次有效操作立即变成 Step 并在 CFG 追加节点，**不是**停录后批量生成 |
| 录制高亮 | 刚操作的元素 | 靶机或截图流上出现录制色高亮框 |
| 停止录制 | 结束捕获 | 停止监听；已生成步骤保留，进入可编辑 |

#### 2.2.1 点击：多层 DOM 完整定位 + 封装展示

靶机里点到的往往是多层嵌套节点（例如 `button > span > icon`）。只记最内层 `role/name` 会在回放时点偏或点不到。

**捕获（存进 Step.locator，回放用）**

1. 被点元素自身的语义属性：`role` / `name`（aria-label、name、可见文本）/ `testId`
2. **祖先链**：从被点节点走到可交互祖先（button/a/input/textarea/contenteditable、role=button/textbox/menuitem/tab 等；**不含** presentation/none/generic）的路径，至少包含 css 路径或 xpath，保证能唯一定位。空 fill 不生成步骤。
3. `target`（哪个 window/webview）

**展示（给人看，不把整串 DOM 甩脸上）**

- 封装成一句人话：`点击 [确定]`、`点击 [搜索框]`
- 详情区默认证「封装名」；需要时再展开完整路径（css/xpath/祖先）

#### 2.2.2 输入：只保留一次填充，不要中间按键

用户输入「你好」时，IME 与逐键会打出 `n` / `ni` / `ni h` / … / `你好` 一串 input。这些**全部是冗余**。

**规则**

- 同一输入框的连续 input/change **坍缩为一条 fill**，值为最终文本
- 结束坍缩的时机：焦点离开、按 Enter、用户点了别的元素、停止录制
- 不能只在「当前 250ms 缓冲」里合并——轮询 drain 跨窗口仍必须合并，否则慢打字会拆成多步
- 展示：`填充 [搜索框] = 你好`

### 2.3 嵌入式点选录制（补充强制，旧实现没有）

等待元素、断言、创建选择组的条件，都依赖「在真实软件里指定一个元素」。工作台表单填 `role=status` 占位**不算完成**。

这不是第二次「开始录制整段流程」，而是嵌在上述步骤里的 **点选子模式**：

```text
用户在工作台点「在软件中点选」
  → 系统进入点选态（顶部提示「请在靶机中点击目标元素」）
  → 用户切到真实软件，点一个元素
  → 系统用与 §2.2.1 相同的完整 locator 写回当前步骤/组条件
  → 退出点选态，工作台详情区显示封装名
```

| 用在哪 | 点选写入什么 |
|---|---|
| 等待条件 waitUntil | 元素类（visible/exists）：目标 locator + 最长等待。文本类（textContains）：可整页搜期望字符串，**不必点选**；详情显示「整页文本，无需点选」，不要写成「尚未选取」 |
| 断言「元素可见/存在」 | 断言目标 locator（未点选时详情才是「尚未选取」） |
| 断言「存在文本」 | 可选点选所在元素；目标文本由用户填写。不点选 = 整页文本 |
| 选择组的执行条件 | 与断言同一套：元素 + 可选期望文本 |

约束：

- 点选必须发生在靶机，不能点工作台截图冒充
- 未连靶机时「在软件中点选」禁用并提示先连接
- 点选过程中不要把这次点击写进普通录制步骤列表（它是在给当前表单填 locator）

### 2.4 手动插入步骤

用户操作类步骤不能手动创建。插入入口只提供 3 类（补充优先：循环不是插入项，是组的 kind，见 §2.5）。

入口：CFG「+」/「插入步骤」

```text
+ 添加步骤
├── 等待时间
├── 等待条件
└── 断言
```

#### 等待时间 `wait`

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| 时长输入 | 设置等待毫秒 | 用户填写（如 3000），保存后 CFG 节点显示「等待 3000ms」 |

用途：等模型回答、等页面加载。不需要点选元素。

#### 等待条件 `waitUntil`

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| 在软件中点选 | 指定等待哪个元素出现/可见 | 走 §2.3 点选录制。**textContains / expr 无 locator 时合法**：执行器搜整页（或表达式），详情文案为「整页文本，无需点选」，不是漏选 |
| 最长等待 | 超时毫秒 | 用户填写（如 10000），超时仍不满足则该步失败（§2.8） |

生成：`等待 [封装名] 出现，最长 10000ms`。

执行语义：在超时内轮询目标断言，成立即继续；**禁止**只 sleep `timeoutMs` 假装等到了。

#### 断言 `assert`

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| 断言类型 | 可见 / 存在 / 文本 等 | 用户选 kind |
| 在软件中点选 | 元素类断言的目标 | 走 §2.3；「元素可见」「元素存在」必须能选元素 |
| 目标文本 | 文本类断言 | 「存在文本 / 文案包含」可填期望字符串 |

断言既用于验证，也可作为选择组的判断条件（与 §2.5 同一套目标模型）。

### 2.5 组：默认一步一组，再打包 / 设分支 / 设循环

补充对编排的要求（覆盖确认稿里单独「插入循环」和「用 assert 搭 if」的旧说法）：

- 连续执行的步骤是 **组**
- **一个步骤默认就是一个单独的组**
- 多选一些步骤可 **打包为组**，组可 **命名**、可 **拆包**
- **选中组** 再设为选择组或循环组
- 选择组的执行条件，和断言的判断目标可以是同一套（点选元素 / 设文本）
- 循环组可设循环次数
- **Else / False 可选**：设为选择组时只建 True；用户在详情点「增加 Else 分支」才出现 False。没有 Else 且条件为假时执行器跳过，不报错
- **原子组不拆包**：一步一组、没有 children 的顺序组不显示拆包

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| 默认组 | 每条新步骤（录制或插入） | 自身即一个顺序组（组内 1 步）。用户不用先「建组」才能选中它 |
| 框选 / 多选 | 选出连续或若干步骤/组 | **鼠标左键按住拖框**选中。松手后在**选区包围盒右侧**（空间不够则上方）弹出紧凑浮动簇，位置按选中节点相对流图画布的包围盒重算（含平移/缩放后），不要钉在画布左上角或页面底。点 CFG 空白取消选区并隐藏浮动钮。Ctrl+点多选仍可用但不在界面上宣传 |
| 打包 | 合成一个命名顺序组 | 弹出后点「打包」**立刻建组**，默认名「顺序组」（或「组 N」）。**禁止** `window.prompt`，也**不要**打包前的内联组名+确定。改名走组上「编辑」详情的组名字段。**新组插在被选步骤原来的位置**，不得把整组挪到 CFG 第一步；选中态落在新组上 |
| 拆包 | 解开组 | 选中**非原子**组 → 拆包：子步骤/子组回到原层级，不删内容。一步一组的原子项不显示拆包 |
| 设为选择组 | if / else | 选中组 → 设为选择。须配置执行条件（§2.3 点选 + 可选文本）。**当前组内步骤进入 True 分支；Else 默认不创建**，可点「增加 Else 分支」或再拖入/框选填入（§5 决策 D4） |
| 设为循环组 | while ×N | 选中组 → 设为循环，填写次数。组内步骤为循环体 |
| 组名 | 识别 | 详情区可改名；CFG 节点显示组名而非内部实现 id |

数据层继续用现有 `Step.children` + `Step.control.kind = sequence | if | while`，不另起第三套 schema（§5 决策 D6）。UI 把每个节点都当「组」操作：叶子 = 只有一步的顺序组。

**选择组与执行器必须一致**：`children[0]` = True，`children[1]` = Else。画反则用户看见的分支和真跑的相反。打包成选择组时，不得把 N 条叶子直接塞进 `children` 当「第 1 条 then、第 2 条 else、其余丢弃」。

### 2.6 CFG 统一展示（图形化控制流图）

确认稿文件名要求 **CFG 统一展示**。本期 **CFG 是步骤的唯一主视图**，且必须以**图形化控制流图**呈现：节点表示步骤/组，有向边表示执行流向。不再并排维护一套可编辑线性列表当主操作面（§5 决策 D2、D11）。

> 关键诉求（用户确认 Figma 原型后补充）：**步骤多的时候，CFG 要能形象地以图示表现步骤运行的结构**——分支往哪分、循环往哪回、顺序怎么串，一眼可读，而不是一列扁平编号。

**图示语义（与执行器一致，画反即谬误）**

```text
Sequence（顺序）        Selection（选择 / if-else）      Loop（循环 ×N）
   ┌──────┐               cond ──┬── True → …            ┌──<──┐
   │ Step │                      │                        │     │
   └──┬───┘                      └── False → …           ▼     │
      ↓                                                 body → ┘
   ┌──────┐
   │ Step │
   └──────┘
```

- **顺序**：竖向链，节点间自上而下的顺序边。
- **选择**：条件节点分叉出 `True` / `False` 两条分支边；`children[0]=True`、`children[1]=Else`（与执行器 `runNode` 一致，§2.5）。
- **循环**：循环体执行后画**回环边**回到循环头，并标注 `×N`；回环边回到循环头而非末步。

基础结构：

```text
Sequence
│
├── Step（默认即一组）
├── Step
│
├── Selection（条件 = 断言同类目标）
│   ├── True → Sequence
│   └── False → Sequence
│
└── Loop × N
    └── Sequence
```

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| 控制流图 | 展示组嵌套与流向 | 顺序竖排+顺序边；选择组分 True/False 分支边；循环画回环边并标 ×N |
| 选中 | 查看/编辑 | 点节点 → 该步截图（查看，`data-layout=shot`），并在该步包围盒旁弹出打包簇。点「编辑」→ 节点旁紧凑详情（`data-layout=flow`）。Esc / 点舞台或 CFG 空白关闭详情 |
| 拖拽调序 | 改执行顺序 | 在 CFG 上拖节点调整兄弟顺序；不得拖进会破坏 if/while 合法性的位置（例如把 True 拖成与条件平级且无提示） |
| 框选 | 打包并选 kind | 见 §2.5 |
| 运行态 | 跟随当前步 | 执行到某节点则该节点高亮；失败变红（图上与列表同步） |
| 删除 | 只删当前 | 选中 → 删除。不级联删后续；依赖坏了由运行时暴露 |

#### 2.6.1 CFG 图示渲染规则

CFG 是**渲染层**，不改数据模型：仍消费 `Step.children` + `control.kind`（§5 决策 D6），图模型与 DOM 渲染分离（`buildCfgGraph(script)` 纯函数产图模型，`CfgView` 只画图与上报点击，不 import 内核/执行器——DIP）。

**节点形态**

| 节点 | 形态 | 标注 |
|---|---|---|
| 叶子步（点击/填充/选择/提交） | 单框 | 封装文案如「点击 [搜索框]」「填充 [搜索框] = 你好」 |
| 顺序组 | 容器框，子节点竖排 | 组名（默认「组 N」）；可折叠为单个节点 |
| 选择组 | 条件框 + 两枝 | 条件文案；每列只标一次 True/False。枝内 sequence 包装若名为 True/False/顺序组，不再印第二层分支头 |
| 循环组 | 容器框 + 回环边 | 组名 + `×N`；循环体在框内 |

**边语义（同层，像 `{}`）**

- 顺序边：只连接**同一父节点下的相邻兄弟**，竖向。不要从组标题再拉一条边进第一个子节点（那就是叠在组角上的大三角）。
- 分支边：条件节点 → `True` / `False` 分支头。True 与 False 之间**禁止**画顺序边。
- 回环边：循环体末兄弟 → 循环头，带 `×N`；不得画成顺序边。

**运行态在图上**

- 当前执行步：高亮（与步骤列表同一状态源，§2.8）。
- pass：通过态着色。
- fail：节点标红 + 截图定位失败元素（§2.8）；图上与列表同步标红，禁止只红一处。
- 重跑：图上状态随重跑重置。

**规模可读性（步骤多时仍可读，本期必须覆盖）**

- **折叠**：打包组可折叠为一个节点（仅显示组名 + kind + 计数），展开再看内部；叶子步默认展开。
- **缩放 / 平移**：画布 `overflow:hidden`，滚轮平移、Ctrl+滚轮缩放、中键/Alt 拖拽平移；**不要**原生滚动条把栏从中缝切开。
- **滚动定位**：选中/运行节点用平移跟进视口。本期**不画 minimap 缩略图**（易与组框叠在一起、看不出作用）。
- **运行跟随**：执行时当前步自动滚入并高亮，用户不必手动找。

**约束**

- 图示必须与执行器真实控制流一致；`children[0]=True` / `children[1]=Else` 画反属最危险缺陷（用户看见的分支和真跑的相反）。
- 未知 `control.kind` 不得白屏：渲染层降级为「未知控制结构」占位节点，硬失败只留在数据入口（`io.ts` / 桥边界）。
- 不把 css/xpath 长串画进节点；节点只显示封装文案，完整路径在详情区展开。

### 2.7 步骤 / 组详情

选中后详情区按类型展示。定位对人显示封装名，完整路径可展开。

| 类型 | 可编辑项 |
|---|---|
| 点击 / 填充 | 封装定位（只读或展开完整路径）；填充还有最终文本 |
| 等待时间 | `waitMs` |
| 等待条件 | 点选目标、`timeoutMs` |
| 断言 | kind、点选目标、期望文本 |
| 顺序组 | 组名、拆包（原子组无拆包） |
| 选择组 | 组名、条件、True/False 说明、「增加/移除 Else 分支」 |
| 循环组 | 组名、循环次数、拆包 |

详情区**不提供**「设为选择组 / 设为循环组 / 设为顺序组」；改 kind 用框选后的浮动钮或选中后的「设为分支组/循环组」。

保存 = 不可变更新当前节点，并给出可见确认（`[data-save-notice]` 或按钮「已保存」后复原）。删除 = 只删该节点。关闭用右上角扇形 X。可运行性交用户判断，不预检依赖。

### 2.8 运行

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| 运行全部 | 从第一步执行整棵 CFG | 逐步执行；CFG 与该步截图同步高亮 |
| 失败 | 立即停 | **立即暂停** → 错误提醒 → 该步标红 → 用该步截图定位失败位置 → 高亮框变红。禁止静默跳过 |

失败后用户改 locator/参数 → 保存 → 再运行。

### 2.9 每步截图与高亮

工作台**不实时渲染**软件当前画面。每产生一步（录制或插入后能定位时）抓一张靶机截图，按 `step.id` 存在内存。导出写进**同一份** JSON 的可选根字段 `shots`（stepId → png data URL），不是第二种格式，步骤对象上不加 png。导入或 `loadScript`/`script.open` 时把 `shots` 灌进舞台 Map；若同一次选择了侧车 `*.shots.json` 也合并。无配图且已连接时仍按叶子补拍（有 locator → `screenshot({ highlight })`）。Agent 生成稿必须带图；经对话打开或未连接导入都能看截图流。

| 场景 | 系统行为 |
|---|---|
| 新步骤产生 | 抓当前页截图，舞台切到这张图，高亮该步元素（回到软件当时所在页） |
| 点选某步 | 舞台显示该步截图 + 高亮，浮标如「点击 / 搜索按钮」 |
| 运行跟随 | 切到当前执行步的截图并高亮，用户不用再点 |
| 失败 | 高亮框变红，标明是哪个元素导致失败 |
| 无截图 | 舞台空白提示「该步尚无截图」（未连接时导入、或补拍失败） |

## 3 端到端场景（验收用）

**A 录制普通流程**：连接 → 开始录制 → 只在靶机点/输入 → CFG 实时出步（点击完整定位、输入一条 fill）→ 停止 → 改参数 → 运行全部 → 逐步高亮。

**B 补等待与断言**：录制完 → 插入等待时间（填毫秒）→ 插入等待条件（点选元素 + 超时）→ 插入断言（点选或填文本）→ 运行全部。

**C 做 if/else**：框选或选组 → 选「分支组」→ 点选条件元素 → True 已有步骤、False 再填 → CFG 图上看到条件分叉两枝 → 运行全部。

**D 做循环**：选组 → 选「循环组」→ 设次数 → CFG 图上看到回环边 + ×N → 运行全部。

**E 失败修复**：运行失败 → 暂停标红定位（图上与列表同步标红）→ 改 locator/参数 → 再跑。

**F 步骤多时的可读性**：录制/插入大量步骤后 → 打包组折叠为单节点、画布缩放平移 → 运行时当前步自动滚入高亮，结构仍一眼可读。
