# 可视化蒙版（UI 壳）功能与交互逻辑规格文档

> 配套：`requirements/requirements.md`、`architecture/architecture.md §2.1/§2.2`、`plan/plan.md` 待做需求 P1–P4。
> 本文档为 **M3 可视化蒙版 UI 壳** 的强制功能与交互基线。实现前须先有对应测试（CODEBUDDY.md §5）。

---

## 0 核心范式（强制）

- **嵌入运行，实时生成**：用户在**靶机软件内部直接交互**（点击、输入、选择），蒙版**嵌入靶机窗口叠加层**，交互发生时**同步捕获并实时生成步骤**，用户无需"操作完回头看"。
- 蒙版不是独立面板播放器，而是**覆盖在靶机之上的操作层 + 步骤工作台**。
- 截图流仅用于"查看特定步骤时在对应页面元素上高亮"，不作为主操作面。

## 1 功能边界

| 模块 | 包含 | 不包含（本期） |
|---|---|---|
| 嵌入交互 | 在靶机内点击/输入即生成步骤；蒙版叠加层显示当前状态 | 不脱离靶机在面板内模拟点击 |
| 步骤生成 | 录制按钮触发；等待步骤；断言步骤 | 不从用户操作"反推"增删改业务步骤 |
| 步骤删除 | 用户主动删除单步；依赖风险交用户判断 | 不自动级联删除 |
| 步骤修改 | 改文本/参数等；可运行性交用户判断 | 不自动校验依赖 |
| 步骤查看 | 点击单步→截图流高亮位置+详情；"运行全部"→从头执行并中途告警 | 不提供脱离靶机的纯文本回放 |
| 版本管理 | 从步切分支、查看历史关系、切换、cherry-pick | 见 §6，不在本期首次交付强制 |

## 2 元素列表、功能与交互逻辑

### 2.0 蒙版叠加层（嵌入靶机）

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| 叠加条（靶机顶部常驻） | 显示录制态/连接态 | 录制中显示"● 录制中"；非录制显示"已暂停"；未连显示"未连接" |
| 浮动控制钮 | 开始/停止录制、运行全部、打开步骤台 | 点击即触发对应动作，无需离开靶机 |
| 当前步高亮框 | 标注刚捕获的交互元素 | 交互发生时在该元素位置绘制高亮框（颜色=录制色） |

### 2.1 连接状态区

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| 连接指示 | 显示靶机连接 | 自动连 9222（P3 前）；连上前录制/运行禁用；断连自动提示重连 |
| 目标选择（P3） | 手动选/填靶机 | P2/P3 落地前维持自动连；落地后此处可切换目标，不写死 |

### 2.2 录制控制（步骤生成唯一入口）

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| 开始录制 | **唯一**生成"用户操作类步骤"的入口 | 点击→向靶机注入交互监听（click/input/change/submit）→用户在软件内操作→**每发生一次交互，实时在步骤列表尾部追加一条对应 Step**（type/locator/参数即时生成，语义化 locator 优先 aria-label/data-testid/text） |
| 停止录制 | 结束捕获 | 点击→停止监听；已生成步骤保留可编辑 |

**步骤生成规则（2.1 用户要求）**
- 用户操作类步骤（点击/填充/选择/提交）：**仅由录制按钮捕获产生**，不提供"手动添加用户操作步"。
- **等待步骤**：手动添加，类型 `wait`（如"等待模型回答"），参数 `waitMs`；不从操作提取。
- **断言步骤**：手动添加，类型 `assert`（kind + 目标），参数来自断言封装 UI；不从操作提取。

### 2.3 步骤列表（增删改查载体）

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| 列表项 | 展示每条步骤 | 显示序号 + 类型图标 + 人话描述（如"点击 [确定]"、"填充 [搜索框]=你好"、"等待 3000ms"、"断言 [标题]=完成"） |
| 选中态 | 标记当前查看/操作的步骤 | 点击列表项→选中→触发 §2.5 高亮查看 |

**2.3.0 控制流分组（CFG 思想，基础模型）**
- 步骤按**程序控制结构**组织：**顺序（Sequence）/ 选择（Selection）/ 循环（Loop）** 三类。
- 分组规则：
  - **顺序组**：一组步骤按序执行（最外层脚本即一个顺序组）。
  - **选择组**：以**断言 `assert` 为判断条件** → 真走 A 分支、假走 B 分支（分支内各自为顺序组）。
  - **循环组**：以 `repeat` 包裹循环体（体内为顺序组），设循环次数 `count`。
- 参考**控制流图（CFG）**：节点=组/步，边=执行流向；组间用控制结构连接。
- **图形化展示**：步骤列表升级为 CFG 视图（树/图），直观呈现组嵌套与流向（§2.7）。
- **版本切出约束（与 Git 对齐）**：只有**最外层顺序执行的步骤/组**支持切出分支；选择组、循环组内部**不可切分支**（否则破坏控制流合法性）。

**2.3.1 增加（2.1）**
- 用户操作步（点击/填充/选择/提交）：仅经"开始录制"捕获，无手动增加入口。
- 手动增加的步骤**最终定为 4 类**（列表区"+"菜单；类型模型仍 OCP 可扩展，但默认 UI 仅暴露这 4 类）：
  - **等待时间** `wait`：参数 `waitMs`（如等模型回答、等加载）。
  - **等待条件** `waitUntil`：参数 `assertion`+`timeoutMs`（等到某断言成立）。
  - **断言** `assert`：参数 `kind`+`target`+期望；**作为"选择组"的判断步骤**（驱动 if/else 走向）。
  - **循环** `repeat`：参数 `count`+循环体（体内为顺序组步骤）。
- 本期不实现 snapshot/note/callScript/setVar 等，预留扩展位，禁止倒改核心。

**2.3.2 删除（2.2）**
- 交互：选中步→删除按钮→**仅删除该步，不级联删除后续步**。
- 依赖风险：**交用户判断**。删除后若该步是后续步运行基础，由用户在"运行全部"时被告警（§2.4 运行全部）自行发现。
- 不实现自动依赖检测、不自动级联删除。

**2.3.3 修改（2.3）**
- 交互：选中步→详情区编辑（如改填充文本、改等待时长、改断言目标）→保存即更新该步（不可变更新，保留历史供 P4）。
- 可运行性：**交用户判断**。修改导致后续不可运行，由"运行全部"告警暴露，不由软件预检。

**2.3.4 查询（2.4）**
- 单步查看：点击列表项→§2.5 高亮查看。
- 运行全部：见 §2.4，改名"运行当前所有步骤"。

### 2.4 运行控制（短名：运行全部）

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| **运行全部**（原"回放"，短名 Run All） | 从第一步起顺序执行全部步骤 | 点击→逐条执行→当前步高亮（P1 自动跟随）→任一步执行失败/找不到元素→**立即暂停并提醒用户**（弹窗+列表标红该步+截图流定位），不静默跳过 |
| 单步运行（可选） | 从选中步开始运行 | 选中步→"从此处运行"→仅执行该步及之后 |

**命名**：对外统称**「运行全部」**（Run All）；内部保留 `runCli` 复用。

### 2.5 高亮与查看（2.4 / 2.5 用户要求）

| 元素 | 功能 | 交互逻辑 |
|---|---|---|
| 截图流舞台 | 显示靶机实时/当前页截图 | 录制时持续刷新；查看/运行时按需刷新 |
| 单步高亮（点击查询） | 在对应页面元素高亮 | 点击某步→截图流定位到该步发生时的页面→在对应元素绘制高亮框+浮标显示"点击/填充文本=xxx"等详情 |

## 3 录制→生成 端到端链路（必须真实跑通）

1. 点"开始录制"→Node 桥向靶机注入监听（exposeFunction 回传交互事件）。
2. 用户在靶机操作→事件经 WS 回传 Node→转 `InteractionEvent`→`Recorder` 转 `Step`。
3. **Step 实时追加到 UI 步骤列表**（非批量、非回头看）。
4. 点"停止录制"→停止监听，步骤留存。
5. 真机冒烟：`verify-ui-live.mjs` 须覆盖"录制→列表实时增长"闭环（runtime-runnability-review 强制）。

## 6 Git 式脚本版本管理（与 CFG 融合的设计，已确认）

> 经用户逐条确认，并与 §2.3.0 控制流分组（CFG）思想融合。实现前须固化为正式设计并更新 architecture §2.2 / requirements UC-10b。

### 6.1 核心映射（版本节点 = 最外层顺序组）

- **一个最外层顺序组（Sequential Group）= 一次 commit**（版本节点）：组内步骤顺序执行，整体作为一个版本快照。
- **选择组 / 循环组 不是版本切出点**：只有最外层顺序步骤/组支持切分支（§2.3.0 约束），保证控制流合法性。
- **一个 Script = 一条分支链**（由若干顺序组 + 内嵌选择/循环结构组成）。
- **整个脚本库 = 一个仓库**（多脚本 = 多分支集合）。
- **CFG 与 Git 关系**：CFG 表达"组内/组间控制结构"，Git 表达"组级版本演进与跨脚本复用"，二者叠加——history 关系图即"分支关系 + 控制流结构"融合视图（§2.7）。

### 6.2 功能清单（git 思想适配，本期 7 项，砍掉 reset/merge/rebase）

| git 概念 | 脚本管理映射 | 交互 |
|---|---|---|
| commit | 每生成/修改/增删一个最外层顺序组 = 一次提交 | 自动产生，不覆盖历史 |
| branch | 从某个最外层顺序组切出新分支 | 选中该组→"从此组开分支"→后续编辑在新分支（选择/循环组内不可切） |
| switch | 切换分支查看不同步骤版本 | 分支列表→切换→CFG 视图渲染该分支 |
| cherry-pick | 跨分支搬运组（含其内部结构） | 他分支选组→pick→作为当前分支新提交追加（允许 pick 后改参数再落，落为新提交） |
| history | 提交关系图（始终有图，融合 CFG） | 节点=顺序组、结构边=控制流；多分支时叠加分支分叉 |
| tag | 标记某版本脚本为基线 | 分支某点打 tag（如"v1 通过版"）→可一键定位 |
| diff | 组/步级差异 | 选两组→显示字段差异（locator/value/kind/结构） |

> **已砍**：reset（用户可直接删/改步，回滚冗余）、merge/rebase（单脚本单分支为主、cherry-pick 搬运即可，多分支并行合并留待后续）。

### 6.3 拖拽重排与版本层（已确认结论）

- 拖拽重排 = 改变提交图的**线性顺序**，须**落在版本层**：每次重排生成新提交，不改写旧提交，保证历史可追溯、不破坏他分支。
- 跨分支 cherry-pick + 重排时，顺序以目标分支当前头为基准追加。
- 重排不得跨越选择/循环组边界破坏结构合法性。

### 6.4 与 UI 的衔接

- §2.3 步骤增/删/改（最外层顺序组级）均产生 commit（不可变更新）。
- 分支切换 → §2.7 CFG 视图渲染对应分支。
- history 视图入口置于 CFG 视图区（始终可看，多分支时显分支分叉）。
