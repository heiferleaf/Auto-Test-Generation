# 交互剧本：每种用法该怎么走、该怎么问

用户可能以任何一种方式进来。识别他属于哪一种，按对应剧本走。
**每一条"要问"都是必须问的，不要自己替用户做决定。**

---

## 通用开场：五个必问（缺一不可）

不管哪种剧本，开工前把下面五件事问清楚。**分批问，不要一次甩五个问题给用户。**

### 第 1 批：能不能测（1 次问完）

> 开始前我需要确认两件事：
> 1. 想测哪个软件？（我说的是软件名字，比如 VS Code）
> 2. 打开它之后按 **F12**，会弹出开发者工具窗口吗？
>
> 顺便问一下你的系统是 **Windows / macOS / Linux**？

拿到答案后：
- 不是 Electron → 如实说明本平台不适用，结束
- 是 Electron → 进入第 2 批

### 第 2 批：怎么连上（视情况二选一）

**如果软件是预置靶机（vscode/codebuddy/workbuddy）且当前是 Windows：**

> 软件在你机器上的可执行文件路径是什么？
> Windows 上一般是 `C:\Users\<用户名>\AppData\Local\Programs\<软件>\<软件>.exe`，
> 可以在开始菜单里右键它 →「打开文件所在的位置」找到。

**如果是 macOS：**

> 需要软件的可执行文件完整路径。注意 macOS 上要的是 `.app` **里面**的二进制，不是 `.app` 目录：
> 访达里找到软件 → 右键「显示包内容」→ `Contents` → `MacOS` → 里面的那个文件。
> 完整路径类似 `/Applications/XXX.app/Contents/MacOS/Electron`。

**用户拿不到路径时的退路**：让他自己带参数启动软件，把端口告诉你（详见 `user-guide.md` 方式 2）。

### 第 3 批：脚本存哪（**生成任何脚本之前必须问**）

> 脚本生成后要存成 json 文件，你希望放在哪个路径？
> 例如 `D:\test\login-test.json` 或 `/Users/me/tests/login-test.json`。

**这条不能跳过。** 原因：
- 脚本是交付物，用户需要能找到它、能版本管理、能下次直接运行
- 工作台里的脚本只存在内存里，刷新即丢
- 路径由用户定，不要自作主张写到项目目录里

拿到路径后，生成脚本时用 `script.export` 得到 JSON 字符串并写入该路径。

### 第 4 批：要不要看网页（生成完之后问）

> 脚本已经生成好了，存在 `<路径>`。
> 我还可以在网页工作台里把它打开给你看——能看到步骤流图、每一步的高亮截图，也可以自己点「运行全部」。需要吗？

要 → `workbench.start` → `script.open` → 把 URL 给他，并提醒"刷新会丢，记得导出"。
不要 → 直接 `actions.execute_steps` 跑，报结果。

### 第 5 批：要不要真跑（执行前问，有副作用时必问）

> 现在要真实执行这个脚本吗？它会**真的操作你的软件**（会真的发消息、真的点提交）。
> 如果软件里当前有没保存的内容，建议先保存一下。

**这步不能省。** 脚本执行是真操作，可能造成不可逆后果（发消息、删数据、提交表单）。
用户明确同意后再调 `actions.execute_steps`。

## 剧本 A：用户描述功能，我生成脚本并跑

> 用户："帮我测一下登录功能。"

1. 走通用开场五批提问
2. `launch-target` / `app.connect`（用用户给的 `appPath` 和端口）
3. `app.list_targets` → 逐层 `page.snapshot`，找到登录框、用户名输入框、密码框、登录按钮、登录后的标志元素
4. **关键提问**：

   > 我看到界面上有这些元素：用户名输入框、密码框、「登录」按钮。
   > 两个问题：
   > 1. 测试用的账号密码是什么？（我可以写进脚本，或者你希望我从环境变量读）
   > 2. 登录成功后，界面上会出现什么**之前没有的**内容？（比如"欢迎回来"、头像、某个菜单项）——这个决定了我的断言怎么验

5. 写 Script JSON（断言必须是第 4 步问到的"新出现的东西"）
6. `script.export` → 写入用户给的路径
7. 问要不要在网页看 → 问要不要执行
8. 执行 → 报结果（失败则给 `failedStepId`，改完用 `fromStepId` 续跑）

## 剧本 B：用户已有脚本文件，让我打开看

> 用户："帮我看看这个脚本。" / "把这个脚本在网页里打开。"

**用户给的是路径** → 直接用：

```
script.import { "path": "<用户给的路径>" }
```

**用户没给路径** → **必须先问**：

> 脚本文件在哪个路径？给我完整路径（比如 `D:\test\login-test.json`），我读一下。

**不要猜测路径，不要去项目目录里翻。** 用户机器上脚本可能 anywhere。

拿到并解析成功后：

1. 告诉用户脚本内容概要：

   > 这个脚本一共 N 步：填用户名 → 填密码 → 点登录 → 等待出现欢迎语。
   > 其中第 4 步是断言，验证"欢迎回来"出现。

2. 问要做什么：

   > 你想让我：
   > 1. 在网页工作台里打开它（能看流图和高亮截图，还能自己点运行）
   > 2. 直接跑一遍报结果
   > 3. 修改它（改哪一步？）
   > 4. 只是检查一下格式对不对

3. 按选择走：
   - 选 1 → `workbench.start` → `script.open { "script": <解析出的对象> }` → 给 URL
   - 选 2 → 问是否确认执行（有副作用）→ `actions.execute_steps`
   - 选 3 → 改完 `script.export` 写回**原路径**（先问用户：覆盖原文件还是另存新路径？）
   - 选 4 → 报校验结果

## 剧本 C：用户想自己录制

> 用户："我自己操作一遍录下来行吗？"

1. 确认是 Electron 软件 + 拿到路径/端口（同通用开场第 1、2 批）
2. `workbench.start` → 把 URL 给用户
3. **引导话术**：

   > 工作台已经打开了：<URL>
   > 操作步骤：
   > 1. 确认顶栏显示**「已连接」**（没连上的话录制按钮是灰的）
   > 2. 点「**开始录制**」——注意录制期间"当前窗口"下拉框会消失，这是正常的，不用管
   > 3. 切到软件窗口，正常操作你要测的功能
   > 4. 切回工作台点「**停止录制**」
   > 5. 用「插入步骤 ▾」补上"等待元素出现"和"断言"
   >
   > ⚠️ 第 5 步很重要：**光有操作不叫测试**，得有断言才能验证功能真的生效。
   > 插入等待/断言时会让你在软件窗口里点选一个元素，**一定要点**，不然它会停在一个占位元素上，验不到点上。
   >
   > ⚠️ 还有：脚本存在网页内存里，**刷新就没了**，录完记得点「导出」。存哪个路径？

4. 用户录完说"好了" → 问他要不要你帮忙检查/补断言
5. 如果要你加工，让他先导出成文件并给路径（你读文件改，改完写回或另存——问清楚）

**注意**：你**不要**替用户调 `record.start` / `record.stop`（那是给人用的界面流程）。
只有在用户明确说"你来控制录制"时才用这两个 Tool。

## 剧本 D：混合模式——用户录制 + 我补断言

> 用户："我录好了，你帮我加上断言。"

1. **先要路径**：

   > 先点「导出」把脚本存成 json，告诉我存的完整路径。

2. `script.import { "path": "..." }`
3. 读一遍，告诉用户你看到了什么：

   > 录了 5 步，都是点击和输入，**没有任何断言**。
   > 也就是现在这个脚本只能证明"点得下去"，证明不了"功能生效了"。

4. **关键提问**（决定断言质量）：

   > 操作完成后，界面上会**新出现**什么？（要那种操作之前没有的东西）
   > 比如成功提示文字、新出现的列表项、跳转后的页面标题。
   >
   > 我需要的是一句**独特的、能代表成功结果的文字或元素**，
   > 不要给我"原来就在界面上的东西"——那样断言恒真，测了等于没测。

5. 补上 `waitUntil` / `assert` 步骤
6. 问：覆盖原文件还是存新路径？→ `script.export` 写入
7. 问要不要在网页看 / 要不要执行

## 剧本 E：用户要我打开脚本但脚本是我刚生成的

这是最常见的完整链路，别漏问：

1. 生成脚本
2. **问存哪**（通用开场第 3 批）
3. `script.export` → 写入
4. **问要不要在网页看**（第 4 批）
5. 要 → `workbench.start` → `script.open` → 给 URL + 提醒刷新会丢
6. **问要不要执行**（第 5 批）
7. 执行 → 报结果

**顺序不能乱**：先落盘（保证不丢），再看网页，再执行。

## 剧本 F：用户只要检查/咨询

> 用户："这个软件能测吗？" / "断言怎么写？"

直接回答，不要启动流程、不要拉起软件。可能的话给一小段 JSON 示例。

---

## 提问的通用纪律

1. **分批问，一次不超过 2 个问题** —— 一次甩五个问题用户会随便答
2. **问可判定的事实，不问技术判断** —— 问"按 F12 会弹窗吗"，不问"是 Electron 吗"
3. **路径一律问用户，永不猜测** —— 脚本存哪、软件在哪、脚本在哪，三个路径都问
4. **执行前必确认** —— 脚本是真操作，有副作用
5. **给默认值让用户选，不要让用户从零构造** —— "存到 `D:\test\login-test.json` 可以吗？" 比 "存哪？" 好答
6. **用户答不上来时给替代方案** —— 拿不到 exe 路径 → 让他自己带参数启动并报端口
