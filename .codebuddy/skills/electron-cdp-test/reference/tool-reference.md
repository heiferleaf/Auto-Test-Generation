# Tool 参考

按"解决什么问题"组织，不是按字母顺序。所有 Tool 的入参里，`null` 与"不传"等价。

---

## 一、让软件进入可控状态

### `launch-target`
**解决**：你无法自己启动一个带调试能力的桌面软件。

```
{ "name": "vscode" }        // 或 codebuddy / workbuddy
{ "name": "vscode", "port": 9244 }   // 可选：指定端口，省略用该靶机默认值
```
返回 `{ name, port, jsonUrl, label }`。**`port` 必须记下并用于后续 `app.connect`**——端口被占用时软件会自动换一个，猜 `9222` 会连错。

⚠️ **平台限制**：这条依赖预置靶机清单，清单里的 exe 路径目前是 Windows 且绑定具体机器的安装位置，
换台机器就找不到。**报"找不到软件"时不要在这条路上纠缠**，直接改走 `app.connect` 的 `appPath`（见下）。

### `target.stop`
**解决**：测完把被测软件关掉。
```
{ "port": 9244 }     // 省略则用本会话 launch-target 返回的端口
```

### `app.connect` / `app.disconnect`
**解决**：建立/断开控制通道。不连接则后续所有操作都不可用。

两种连法：

```
// 连已带调试端口运行的软件
app.connect { "port": <launch-target 返回值，或用户告知的端口> }

// 由平台拉起软件：给可执行文件位置，平台自动加 --remote-debugging-port
app.connect { "port": 9244, "appPath": "<可执行文件完整路径>" }
```

**`appPath` 要可执行文件本身，不是目录**：

| 平台 | 传什么 |
|---|---|
| Windows | `C:\...\XXX.exe` |
| macOS | `/Applications/XXX.app/Contents/MacOS/Electron`（`.app` 是文件夹，直接传启动不了） |
| Linux | `/usr/bin/code` 之类可执行文件路径 |

用 `appPath` 时平台会自己启动进程并轮询调试端口直到就绪（约 15s 超时）。
这条是**跨平台的首选路径**——`launch-target` 依赖的靶机清单目前是 Windows 且绑定具体机器。

**传了 `appPath` 仍超时**：九成是路径给错了。最常见的是 macOS 传了 `.app` 目录（它是文件夹，
真正的二进制在 `XXX.app/Contents/MacOS/` 里）。排查步骤见 `reference/troubleshooting.md`。

`app.disconnect {}` 断开连接。

### `workbench.start` / `workbench.stop`
**解决**：打开/关闭网页工作台（给人看脚本和截图用的界面）。
```
workbench.start {}    // 返回 { url }，端口占用时可能不是 5173
```
Agent 自己执行脚本时不需要它；只有要把脚本推给人看时才开。

## 二、看懂界面

### `app.list_targets`
**解决**：**回答"这个软件里有哪些可以操作的页面层"**。

这是必做步骤，不是可选项。Electron 软件常把聊天区、侧边栏做成独立的嵌入层，目标控件往往不在主窗口里。

返回 `[{ id, type, title, isMain }]`，`type` 为 `page`（主窗口）或 `webview`（嵌入层）。**`id` 要写进步骤的 `target` 字段**。

### `page.snapshot`
**解决**：**回答"这一层上有哪些可以操作的控件"**。

你看不见界面，这是获取界面信息的唯一途径。
```
{ "targetId": "<list_targets 的 id>" }   // 省略/null = 当前层
```
返回可交互节点列表，每个节点带 `role`（控件类型）、`name`（名称）、`text`（文字）。据此决定点什么。

**没找到目标控件时，换一个 `targetId` 再快照**，不要就此下结论说"没有这个控件"。

### `page.screenshot`
**解决**：看界面长什么样（返回 png base64）。快照已能满足大部分需求，截图用于需要视觉确认时。
```
{ "targetId": "...", "highlight": { "role": "button", "name": "发送" }, "savePath": "..." }
```
`highlight` 会在图上高亮指定元素；`savePath` 可落盘供人工查看。

## 三、执行测试

### `actions.execute_steps`
**解决**：**真正跑一遍脚本**，这是测试的主体动作。
```
{ "script": <Script 对象或 JSON 字符串>, "fromStepId": "s2" }
```
返回 `{ ok, failedStepId }`。失败时改 JSON 里那一步，可用 `fromStepId` 从指定步骤续跑，不必重头。

### `script.open`
**解决**：把脚本推进网页工作台，**让人看到步骤列表、CFG 图和逐步截图，由人决定何时运行**。

与 `actions.execute_steps` 的区别：后者是你自己跑拿结果，前者是交给人在界面里操作。工作台在已连接状态下会自动为各步骤补拍高亮截图。
```
{ "script": <Script 对象或 JSON 字符串>, "workbenchUrl": "<可选，见下>" }
```
返回 `{ opened, url, delivered, steps }`。**`url` 是脚本实际推进的工作台地址，必须原样告诉用户** —— 不要自己拼地址。`delivered` 是真正收到脚本的网页数。

**它只推给唯一确定的工作台。** 下面两种情况它报错而不是挑一个推过去 —— 这是刻意的，推错了比报错糟得多：

- **本机开着多个工作台实例**：它无从知道用户在看哪一个。问用户，把那个地址作为 `workbenchUrl` 重传。
- **那个工作台上没有打开的网页**：脚本没到人眼前。让用户打开页面后重试，或改用 `workbench.start` 新开一个。

报错时它不会改推到别处，更不会报成功。撞上这两条看 `troubleshooting.md` 的「工作台」一节。

```
{ "script": <Script 对象或 JSON 字符串> }                      // 工作台唯一时
{ "script": {...}, "workbenchUrl": "http://localhost:5175/" }  // 有多个工作台时必须显式指定
```
返回 `{ opened, url, delivered, steps }` —— **`url` 是脚本实际推到的地址，必须原样转告用户**；`delivered` 是真正收到脚本的网页连接数。

**只推给唯一确定的工作台。** 下面三种情况它会**报错**而不是挑一个推过去（宁可报错让你去问用户，也不能推错还报成功）：

| 报错说的是 | 你该怎么做 |
| --- | --- |
| 没扫到工作台 | 先 `workbench.start`，拿它的返回值再 `script.open` |
| 扫到多个实例（报错里会列全部地址） | **不要猜**。问用户在看哪一个，把它作为 `workbenchUrl` 重试；或 `workbench.start` 新开一个 |
| 目标上没有打开的网页（`delivered` 为 0） | 让用户在浏览器打开该地址后重试，或 `workbench.start` 新开 |

**省事路径**：先 `workbench.start` 再 `script.open`。前者会把 URL 原样返回，后者就直接用它，根本不走扫描，也就不会撞上多实例。

### `script.import`
**解决**：校验并解析一份脚本（写完后自检，或读取已有文件）。
```
{ "path": "x.json" }   // 或 { "json": "<字符串>" }
```

### `script.export`
**解决**：把脚本序列化成 JSON 字符串落盘。
```
{ "script": <Script 对象> }
```

## 四、单步探针（辅助）

**定位**：验证不确定的定位，确认后**仍要写回 Script JSON**。禁止连调多次代替写脚本——探针不产生可复用的产物。

| Tool | 用途 |
|---|---|
| `page.click` | 点一次，确认 locator 对不对 |
| `page.fill` | 填一次值 |
| `page.wait` | 等时长或等某段文字出现 |
| `page.waitUntil` | 轮询直到断言成立 |
| `assert.run` | 执行单条断言 |

## 四·五、视觉断言（`visionPrompt`）

**解决**：界面状态**说不出来、只能看出来**的时候，交给视觉模型判定。

用在文字和控件属性都表达不了的东西上：图标长什么样、配色对不对、布局有没有错乱、图表趋势是否向上、画布里画了什么。

**前提：必须先让用户配好视觉模型**（见 `reference/talk-scripts.md` 的 API Key 引导话术）。没配好时这一步直接算失败，不会静默跳过——静默跳过等于测试造假。

### 怎么用

提示词写在断言的 `value` 里，不新增字段：

```json
{ "id": "s3", "type": "waitUntil", "source": "agent", "target": "<层 id>",
  "params": { "timeoutMs": 15000,
    "assertion": { "kind": "visionPrompt", "value": "界面上是否出现了成功的绿色对勾图标？" } } }
```

| 字段 | 是否必填 | 说明 |
|---|---|---|
| `kind` | 必填 | 固定 `visionPrompt` |
| `value` | 必填 | 判定提示词，**要写成一句能回答"是 / 否"的问题** |
| `locator` | 可选 | 给了就只截这个元素；不给截整屏 |

**提示词写法**：问一个明确的是非题，别问开放问题。

| 好 ✅ | 差 ❌ |
|---|---|
| "界面上是否出现了成功的绿色对勾图标？" | "界面看起来正常吗？" |
| "右上角的圆点是红色的吗？" | "这个图标是什么含义？" |

**截局部比截整屏准**：能定位到元素就给 `locator`，范围越小判定越稳。

### 返回值

模型返回 `{ passed: boolean, reason?: string }`。**只有严格 `true` 才算通过**——模型返回别的东西（没返回、返回字符串 "true"、返回非 JSON）一律按不通过处理。

### 失败说明的含义

| 返回的原因 | 是什么问题 | 怎么修 |
|---|---|---|
| 缺少提示词 | 脚本里 `value` 是空的 | 补上提示词。这是脚本写错了 |
| 当前环境不支持截图 | 这条链路拿不到画面 | 改用文本断言，别在这条路上耗 |
| 截图为空 | 拿到的画面是空的 | 软件窗口可能没渲染出来，前面加个等待步骤 |
| 未配置：`<原因>` | **最常见**。视觉模型没配好 | 按话术引导用户配端点；用户没有就改成语义断言 |
| 调用失败：`<原因>` | 请求发出去但没成功 | 多半是地址或密钥不对。注意：密钥片段在这些提示里是打码的，正常 |
| 判定不成立：`<模型给的依据>` | **模型真的看了，认为不成立** | 这是有效结论。要么断言预期本身错了，要么功能确实有问题 |

最后一条和前面几条性质不同：前面是"没跑成"，这条是"跑了，结论是不通过"。**报告时要分开说**，别混成一句"视觉断言失败"。

### 成本与稳定性

- **比文本断言慢**：每次判定要等模型返回。超时给宽一点，建议 `timeoutMs` 15000 起步。
- **要花钱**：每跑一次就调一次模型。循环里放视觉断言会成倍放大，不要在 `while` 组里用。
- **不如文本断言确定**：同一张图模型未必每次给同一结论。**能用 `textContains` / `exists` / `visible` 判定的，就不要用视觉断言。**

### 密钥不会进脚本

端点地址、模型名、密钥都只存在运行环境里（环境变量或用户家目录的配置文件），**不写进 Script JSON**。脚本可以放心导出、提交版本库、分享给别人；对方要跑视觉断言，得自己配一次端点。

## 五、录制内核（默认不用）

人在真实软件窗口操作时，中台会自动录成步骤，**你不要替他按"开始录制"**。

只有用户明确要求你控制录制内核时才用：
```
record.start {}  →（人操作完）  record.stop {}  →  record.get_steps {}
```

## 跨 Tool 的通用约束

- **端口只用 `launch-target` 的返回值**，或用户明确告知的号码
- **`targetId` 省略或 `null` = 当前层**，不要把 `null` 当成一个 id 传
- **缺参当缺省**：跨 JSON 边界 `null` 等同未传，不会当成有效值
- **连接前不许陈述软件状态**：`app.connect` 返回成功之前，没有"已就绪"这回事。用户说了软件名
  只代表指定了目标，不代表它已经启动 —— 想确认就用 `app.list_targets` 探（无副作用，连不上会明确报错）
- **工具不可用就停手报给用户**：不要退回去读源码、执行 npm script 或自己拼命令行，那不是用户要的
